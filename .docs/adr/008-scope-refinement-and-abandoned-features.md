# ADR-008: Scope Refinement and Rejection of Offline Cache, Password Expiry Audit, and Mutation Idempotency

## Status

Accepted（Issue #158, Issue #271 クローズ、および要件・設計書のスリム化に伴う設計決定）

## Context

プロダクトの長期ロードマップや初期要件において、以下の 4 機能が計画・検討されていた：
1. **PWA 完全オフライン閲覧（FR-PWA-03 / Issue #158）**: IndexedDB に暗号化レコードをキャッシュし、完全オフライン環境で復号閲覧可能にする。
2. **アカウント健康診断・定期棚卸しリマインド（FR-REC-16 の一部 / Issue #271）**: 一定期間更新のないレコードを検知し、ユーザーに棚卸し・変更を促す警告を表示する。
3. **クリップボード自動消去**: パスワードヒントをコピー後、30〜60秒後にクリップボードを自動消去する。
4. **Mutation Idempotency Key 機構（FR-AUTH-07 の一部）**: ネットワーク切断やセッション切れ時の重複送信防止・再実行機構。

これらの機能について、PoohMa のコア設計思想（E2EE ゼロ知識アーキテクチャ、家族除名時の即時無効化、NIST SP 800-63B 基準、Single Source of Truth、KISS 原則）と照合し、継続すべきか否かを審査した。

## Decision

上記の 4 項目をすべて**【正式に見送り・不採用】**とし、公式仕様書（`requirements.md`, `features.md`）から削除する。

### 1. PWA 完全オフライン暗号キャッシュの不採用

- **技術的根拠**:
  1. **除名時アクセス即時無効化の担保不能（セキュリティ破綻）**: 家族グループから除名（キック）された元メンバーが、端末をオフラインにしたまま IndexedDB 内のローカルキャッシュを用いて旧データをいつまでも復号閲覧できてしまう。PoohMa の不変条件である「除名・鍵更新時のアクセス即時剥奪」を暗号学的に担保できない。
  2. **Single Source of Truth の維持**: Convex のリアルタイムリアクティブ購読にデータソースを一本化し、クライアントキャッシュとの二重管理・同期競合・ゾンビデータリスクを排除する。
- **代替策**: Web App Manifest（`public/manifest.json`）による PWA スタンドアロン起動（ホーム画面追加・専用アプリアイコン・フルスクリーン表示）を提供する。


### 2. 定期棚卸し・長期未更新警告の不採用

- **技術的根拠**:
  1. **NIST SP 800-63B ガイドライン（§3.1.1.2）準拠**: 現代のデジタルアイデンティティ標準では「認証パスワードの定期的な変更の強制」は、予測しやすいパターンの使い回しを誘発しセキュリティを低下させるため非推奨とされている。パスワード管理サービスである PoohMa において、保存レコードの定期的変更・棚卸しを催促する通知を導入することは、この標準の精神に反してユーザーに無意味なパスワード変更を強いかねない。
  2. **プロダクト UX 思想との乖離**: PoohMa は家族間で「固定的な思い出の手がかり（実家Wi-Fiなど）」を共有するサービスであり、更新頻度が低いこと自体は健全である。無用な警告でユーザーに不安やプレッシャーを与えない。
- **代替策**: 共有データの透明性を高める「閲覧履歴ログ（Audit Log・Issue #268）」のみを将来検討として残す。

### 3. クリップボード自動消去の不採用

- **技術的根拠**: モバイルブラウザのサンドボックス制約（バックグラウンド遷移後に Clipboard API を操作できない）が存在し、完全な消去を保証できない。また、ユーザーが他アプリでコピーした重要なテキストを不意に上書き消去してしまう破壊的副作用（UX 破壊）を招く。

### 4. Mutation Idempotency Key 機構の不採用

- **技術的根拠**: PoohMa ではすでに `FR-REC-28`（暗号化ドラフト自動退避・復元基盤）が完全稼働しており、セッション切れやバックグラウンド終了後もローカル暗号化ドラフトから入力値が安全に復元される。Convex の接続維持による保留中 Mutation の自動再送保証の範囲を超えて、セッション再認証後の新規 Mutation 再実行に対してまで過剰な独自 Idempotency Key 追跡テーブルや二重送信防止機構を導入することは、「念のため二重にする」過剰冗長化（KISS 原則違反）である。

## Consequences

- 要件定義書および機能一覧から実現不可能な過剰要件が排除され、公式ドキュメントが現在と将来の真の姿（Single Source of Truth）を反映する。
- オフラインDB同期や複雑な Worker パイプラインを抱え込まずに済み、保守性・信頼性が大幅に向上する。
- 将来の開発において「オフライン閲覧を復活させよう」「定期変更リマインドを追加しよう」といった再検討が発生した際、本 ADR を参照することでセキュリティ破綻や標準規格との衝突を即座に再認識できる。
