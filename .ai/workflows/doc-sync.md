# Documentation Cross-Consistency & Update Workflow

PoohMa の設計書・ドキュメント群は多面的（データモデル、認証フロー、API一覧、状態管理責務表、セキュリティ境界）に構成されているため、**1箇所の変更が複数セクション・複数ファイルに波及します**。コード変更時は、本ワークフローに従って横断確認を行い、古い仕様の残骸を漏れなく同期してください。

---

## 1. ドキュメント更新チェック手順（Doc-Sync Gate）

コードの変更（新機能実装、リファクタリング、PR レビュー指摘対応のいずれも含む）を行った際は、**「テストが通ったから完了」と判断してはならない**。以下の 4 ステップを必ず踏み、ドキュメント同期を完了させてからコミットすること。

1. **計画段階**: 変更内容に関連するドキュメント（要件定義、ER図、API仕様、環境変数、脅威モデル等）の更新要否を事前に特定する。
2. **実装・レビュー段階**: コード変更差分とドキュメントの記述が完全に一致しているかをセルフレビューする。「レビュー対応で追加されたUX改善・ボタン配置変更・セキュリティ補強」もすべて仕様変更として扱う。
3. **コミット前（Doc-Sync Gate - 必須関門）**:
   - `pnpm check:doc-sync` を実行し、変更差分から同期が必要なドキュメント候補を機械的にチェックする。
   - `git diff --stat` を実行し、変更・追加されたファイル群を俯瞰する。
   - 以下の「2. ドキュメント横断整合性チェックマトリクス」および「5大公式設計書」と機械的に突合する。
   - 変更がある場合は、コードコミットと同一のコミットまたは先行コミットとしてドキュメントを更新する。
   - `pnpm check:knowledge` を実行し、`.ai/` 内のコード参照切れ（陳腐化）がないことを確認する。
4. **品質検証**: `pnpm check`, `pnpm typecheck`, `pnpm test`, `pnpm build`, `pnpm test:e2e` を実行して全検証を通過することを確認する。

---

## 2. ドキュメント横断整合性チェックマトリクス

変更対象のキーワード（関数名、テーブル名、ストレージ種別、コンポーネント名、環境定数等）で設計書全体を `grep` し、以下のマトリクスに従って全箇所を同時に更新してください。

| 変更の種類 | 確認・同期すべきドキュメント箇所 | 具体的なチェック内容 |
| :--- | :--- | :--- |
| **スキーマ・テーブル構成** | `code-design.md`「4.1 ER概要」「4.2 テーブル定義」、`.ai/domain.md` | 新規テーブル、フィールド追加、型変更、インデックス追加 |
| **Server Function / Convex 関数** | `code-design.md`「7. API設計」「7.6 Server Functions」表、`.ai/architecture.md` | 関数の追加・削除・改名、認可ビルダーの変更 |
| **認証イベント・フロー** | `code-design.md`「5.2 認証フロー」「5.6 ログアウトフロー」、`security-model.md`、`.ai/invariants.md` | ログイン維持、セッション延長、トークン更新、ログアウト処理 |
| **状態管理・ストレージ・ドラフト** | `code-design.md`「8.4 状態管理表」、`security-model.md`、`.ai/patterns.md` | localStorage / IndexedDB のキー体系、TTL、暗号化、ライフサイクル破棄 |
| **UI体験・コンポーネント・配置** | `features.md`「3. レコード管理」「4. UX」、`requirements.md`「FR-REC / NFR-UX」、`DESIGN.md`「Inputs / Buttons / Footers」 | 固定フッター、ボタン配置・サイズ、変更インジケーター、レスポンシブ仕様 |
| **暗号化・鍵階層・E2EE** | `code-design.md`「6. 暗号化設計」、`security/e2ee.md`、`security/security-model.md`、`security/threat-model.md` | 新規鍵（draftDEK等）、ラップ方式、E2EE境界、端末抽出・マルチアカウント脅威防御 |
| **動作環境・外部連携・API** | `features.md`「6. データ連携」、`requirements.md`「NFR-ENV」、`code-design.md`「2. 技術スタック」 | サポートブラウザ最低バージョン、新規 Web API（BroadcastChannel等）、CMS・SaaS連携 |
| **データ移行・UID引き継ぎ** | `code-design.md`「4.1 ER概要」「5.2 フロー」「7.1 API表」、`security-model.md`、`.ai/domain.md` | アカウント引き継ぎ、家族移行、Export Vault |

> **Pitfall**: 設計書の「ある1セクションだけ更新して他のセクションに古い記述が残る」こと、および「レビュー指摘対応で追加されたUX改善をバグ修正と錯覚してドキュメント更新を怠る」ことが、最も頻繁に発生する失敗パターンです。必ず `git diff --stat` を起点にプロジェクト全体で横断同期を行ってください。
